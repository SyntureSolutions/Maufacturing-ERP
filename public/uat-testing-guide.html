TC-P2P-01: Purchase Order Creation with Inline Triggers Screen: /dashboard/purchase

  2. Select Supplier National Agro Commodities Ltd. Notice payment terms auto-populate.

  4. Notice Unit Rate auto-populates as Rs. 320.00. Subtotal calculates as Rs. 64,000.00.
  5. Verify Tax Breakdown (IGST 12% if inter-state or CGST 6% + SGST 6% if intra-state). Save PO.
Expected Result: PO status becomes APPROVED / ISSUED with unique sequential PO Number (e.g. PO-2026-0042).
TC-P2P-02: Goods Receipt Note (GRN) & FEFO Batch Tagging Screen: /dashboard/inventory or GRN Tab
  1. Click Create GRN against the approved PO.
  2. Verify PO line items are imported with Ordered Qty = 200 PKT. Enter Received Qty = 200 PKT.
  3. Input mandatory Batch Details: Batch No: BAT-ALM-2610A, Expiry Date: 30/04/2027.
  4. Select Warehouse Location / Bin: Bay-A / Cold Storage Rack 2. Submit GRN.
Expected Result: GRN is generated; stock moves into Inspection Hold / Quarantined awaiting QC sign-off.
TC-P2P-03: Quality Inspection (QC) & NCR Defect Disposition Screen: /dashboard/quality

Log in as quality@inventorypro.com. Locate GRN BAT-ALM-2610A under pending inspections.

Scenario A: QC Pass (Accepted)
  • Input parameters: Moisture < 5%, Microbial: Negative.
  • Status: Select PASS & Click Submit.
  • Result: 200 PKT releases immediately into Available Free Stock for sales allocation.
Scenario B: QC Fail → Auto-NCR
  • Status: Select FAIL • Reason: Pouch seal defect.
  • NCR pop-up triggers: Severity: Major.
  • Disposition: Return to Vendor.
  • Result: Defect logged, vendor debit note flagged, stock blocked from sale.
Verified: QC pass activates inventory; QC fail isolates lot in Reject Store with an NCR ticket.
TC-P2P-04: 3-Way Match Vendor Bill & Payment Release Screen: /dashboard/finance • Vendor Bills
  1. Log in as finance@inventorypro.com. Check "Awaiting Vendor Bill" queue.
  2. Select PO & GRN. Click Generate Vendor Bill. Input Vendor Invoice No: NAC/INV/9821.
  3. Verify 3-way match: PO Price (Rs. 320) x Accepted GRN Qty (200) = Rs. 64,000 + GST 12% = Rs. 71,680.00.
  4. Click Release Payment → Select Bank: HDFC Current A/c • Mode: NEFT • Enter UTR: HDFCN26289012345.
Expected Result: Payment voucher posts to Bank Ledger; Vendor Bill status changes to PAID; PO payment badge updates.

Prodexa ERP • UAT Testing Manual Section 7: Edge Cases & System Integrity

7. Edge Cases, Security & Compliance Checklist

Stress-test validation boundaries, exception conditions, and regulatory compliance rules:

SEC-01: Zero Stock / Over-Fulfillment Blockage Negative Test Case
Action:
Attempt to generate a Delivery Challan for 500 PKT when available free batch stock is only 100 PKT.
Expected:
System blocks transaction with warning: "Insufficient stock: requested 500 PKT exceeds available batch balance (100 PKT). Please plan a Work Order or PO." Negative inventory is strictly prevented.
Pass / Fail: Stock validation barrier strictly enforced.
SEC-02: Expired Batch FEFO Blockage Food Safety Compliance
Action:
Create an inward batch with an expiry date set in the past (e.g. 10/10/2025). Attempt to allocate this batch to an active Sales Order.
Expected:
FEFO allocation engine automatically excludes expired lot from eligible pick lists. Batch is flagged EXPIRED and quarantined to prevent contamination.
Pass / Fail: Expired lots prevented from order picking.
SEC-03: Role-Based Authorization Barriers Security Audit
Action:
Log in as sales@inventorypro.com and attempt to access /dashboard/finance or approve a vendor payment voucher.
Expected:
Server returns 403 Forbidden or redirects to unauthorized warning. Navigation menus restrict unauthorized action buttons.
Pass / Fail: Role permissions strictly gated.
SEC-04: Network Fault-Tolerance & In-Memory Fallback Reliability Test
Action:
Trigger rapid customer/supplier creations or sales workflows even if cloud database connection experiences high latency or timeout.
Expected:
API routes seamlessly fall back to local in-memory mock stores, returning HTTP 200/201 responses without server crash (zero 500 error screens).
Pass / Fail: Seamless fallback operational.
